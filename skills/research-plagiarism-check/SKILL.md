# 연구 문서 표절·인용 점검

**연구 문서를 만들거나 크게 고쳤으면 끝내기 전에 이 점검을 한 번 돌리고 결과를 알린다**(사용자가 따로 말하지 않아도).
점검은 읽기만 한다 — 원고를 고치는 것은 사용자에게 보고서를 보여 주고 동의를 받은 뒤에.

## 순서

파이썬은 pypdf 가 있는 것(IRIS: `C:\IRIS\_agent\runtime\venvs\document-mcp\Scripts\python.exe`, `-I` 로 실행).

1. **참고 자료 폴더 정하기** — 사용자가 이 글에 쓴 자료(PDF·docx·hwpx·hwp·txt·md)가 모인 폴더. 모르면 묻는다
   (추천 기본값: 원고와 같은 폴더의 `참고자료` 폴더). 폴더가 없으면 내 자료 대조는 건너뛰고 2~4만 한다.
2. **웹 검색할 문장 고르기**
   `python scripts/plagiarism.py 원고 --refs 폴더 --pick-web 8` → `web_candidates`(특이한 문장 + 따옴표 검색어).
3. **웹 검색** — 후보마다 자기 웹 검색 도구로 `query` 를 그대로 찾는다(추가 비용 없음). 결과를 JSON 파일로 적는다:
   `[{"id":"w1","verdict":"same|similar|none","url":"…","title":"…","note":"한 줄 설명"}]`
   - same = 거의 같은 문장이 있음 · similar = 표현이 많이 겹침 · none = 못 찾음. 판단이 애매하면 similar.
   - 검색 결과에 없는 내용을 지어내지 않는다. 못 찾으면 none.
4. **보고서 만들기**
   `python scripts/plagiarism.py 원고 --refs 폴더 --web 웹결과.json --out 원고이름-표절점검.html`
   → 표준 출력 JSON(요약) + 형광펜 HTML 보고서. 보고서를 브라우저로 띄운다.
5. **알리기** — 위험도·겹친 비율·고쳐야 할 곳 개수·참고문헌 목록 문제를 쉬운 말로 요약하고, 고칠지 묻는다(추천: 출처 없는 곳부터).

## 결과 읽는 법

- `출처 표시 없음` — 자료와 30글자 이상 그대로 같은데 출처가 없음 → 가장 위험. 출처를 달거나 바꿔 쓴다.
- `출처는 있으나 원문 그대로` — 출처는 있지만 따옴표 없이 길게 옮김 → 따옴표(직접 인용) 또는 바꿔 쓰기.
- `정상 인용` — 따옴표 + 출처. 위험 비율에서 뺀다.
- 참고문헌: `목록에 없는 본문 인용`(본문엔 있는데 목록에 없음) · `본문에서 쓰지 않은 목록`.
- 한계: 의미만 같고 글자가 다른 '바꿔 쓴 글'은 못 잡는다 — 수치는 최소한이라고 꼭 말한다. 스캔 PDF(글자 없음)는 건너뛴다(`skipped`).
